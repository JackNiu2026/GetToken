# 普通商品受理与询价

当前五类商品均未受理。公开 `site.config.mjs` 中联系渠道、服务主体、支持时段，以及逐商品的可供货档位与期限经核实后，才可启用对应 `inquiries` 配置；重新生成网站并验收静态与运行时状态。支付二维码和数字价格不能自动开启受理。

受理人员需在商家的受控登记工具中记录：询价编号、日期、最少必要联系方式、产品与权益、意向期限、资格核对结论、报价币种与有效期、交付及退款约定、处理人和状态。不要把个人资料提交 GitHub。浏览器仅生成咨询摘要，不生成持久订单，真实成交以人工登记和核款证据为准。

状态建议：待确认 → 已报价 → 用户接受 → 已核款 → 已交付 / 无法交付；取消及退款记录原因和处理结果。询价无需密码或 Session Key。报价前不能承诺未核实库存、固定时效、季度/年度官方订阅或账号权限。

启用前做一次真实支持渠道的测试咨询，确认支持方能收到、登记、回复；渠道停用或供应变化时立即关闭对应受理配置。未取得该证据时，只能验收“错误购买入口已修复”。
