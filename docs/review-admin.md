# 简单审核后台

入口：[https://gettoken.cc/verify/admin/](https://gettoken.cc/verify/admin/)。继续使用原管理员密码，部署不会重置密码、会话或提交记录。

首次登录或忘记密码时，在服务器终端执行 `sudo gettoken-verify passwd`，按提示输入两次至少 12 位的新密码。输入不会回显；更新后已有管理员会话失效。不需要在聊天、GitHub、URL 或公开配置中提交密码。首次安装生成的随机初始密码仍只在服务器 root 可读的私有文件中，网页不提供公开注册或免登录重置。

操作流程：

1. 登录后默认查看“待审核”，也可选择已通过、未通过或全部提交。列表只展示打码 Key、受理编号、提交时间与预计剩余时间；支持按编号、Key 末 4 位搜索，每页 30 条。
2. 点击受理编号查看提交的完整 Session Key、时间、展示授权和处理日志；需要时点击“复制 Session Key”。手机点选后会滚动到详情。完整凭据只有登录后的详情接口可取，退出后会清空页面中的记录与详情。
3. 填写“审核说明”，选择“通过”或“未通过”，核对确认框后保存。审核说明必填且用户可见，不能包含 Session Key。取消确认不会保存；网络失败保留当前输入，可重试；已经出结果的记录不能被再次覆盖。
4. 用户通过原浏览器或专属私密查询链接查看结果和审核说明。本站处理结果不代表 Claude 官方认证结果；仅 Key 提交不产生支付或退款。

后台每 30 秒刷新列表与统计，也可点击“刷新提交”，不会改写正在输入的审核说明。网络异常显示重试提示；历史淘宝与收付款记录仍可在“全部提交”中查阅和继续处理。

预计审核时间统一为 **12 小时**，从处理开始时计算（仅 Key 提交即提交时）。升级时将仍在审核且采用原 24 小时窗口的记录按原开始时间改为 12 小时，记录一次时长调整日志；不会重置起点，也不会改动已出结果的历史截止时间或退款约定。超时仅标记超时，持续等待人工结果，不会自动通过或失败。

管理员登录采用服务器会话及 HttpOnly / Secure / SameSite=Strict Cookie；变更接口验证后台来源请求头。页面不被搜索引擎收录；公开结果只显示打码 Key，查询依然需要专属访问凭证。

验收包括：真实 HTTP 鉴权、必填说明、凭据误粘贴拦截、重复判定冲突、12 小时新记录和历史迁移、超时不判定，以及真实浏览器从提交到后台录入再到用户查询的闭环。测试全部使用内存数据库和虚构资料。生产部署后只读检查入口、脚本、审核时长以及匿名访问记录接口返回 401。
