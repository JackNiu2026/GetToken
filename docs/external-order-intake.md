# 淘宝订单资料受理（历史说明）

已被用户最新要求替代：新提交仅需 Session Key，不再需要淘宝订单号或人工核单。当前操作见 [Session Key 提交](session-key-intake.md)。以下仅供历史记录与售后运维参考。

本轮只支持淘宝订单号，不上传截图，不展示微信或在线付款入口；未提供真实淘宝商品链接，因此没有购买跳转。现有页面布局、配色与 CSS 文件保持不变，表单沿用现有组件样式。

用户填写本人 Session Key、完整淘宝订单号（10–32 位数字），确认授权后提交。后台已设置密码时默认允许资料提交；`VERIFY_ACCEPT_EXTERNAL_ORDERS=false` 可独立暂停。`VERIFY_PAY_MODE=off` 应保持，站内新建与付款接口关闭。旧财务记录、回调、查单和退款补偿保留，避免遗失历史资金状态。

提交生成「待核单」受理记录，绝不自动视为付款。后台 `/verify/admin/` 默认待核单列表，可按淘宝订单号搜索，详情仅授权管理员可查看完整订单号及 Session Key。

1. 在淘宝商家后台核对订单归属、购买内容、实付金额及交付/售后约定。本站未接入淘宝交易 API，不能证明付款真实性。记录核对摘要，选择核单通过或未通过。拒绝原因用户可见，任何备注都不得包含凭据。
2. 核单通过进入处理中，从核单时刻计算预计 24 小时。计时结束不会自动判定结果；后台填写交付证据摘要或未通过原因后录入结果。
3. 未通过转淘宝售后。商家按原订单约定在淘宝处理退款，核对凭证后在本站登记摘要；登记只改变本站状态，不发起任何支付或退款，也不代表平台已到账。本站不推断淘宝实付金额、退款金额或固定退款时限。

原浏览器可输入淘宝订单号或受理编号查询；跨设备使用完整私密查询链接。链接含访问凭证，不能公开。API 仍要求私密访问请求头，不能只凭订单号公开查询。浏览器仅保存受理编号、随机查询凭证和淘宝订单号的 SHA-256 映射，不保存完整 Session Key 或淘宝订单号。链接遗失时通过淘宝原订单核实身份后，由管理员用现有私密查询凭证恢复工具处理；不能将订单号当作身份认证。

重复淘宝订单号返回 409，不暴露已有受理编号或查询凭证，不创建第二笔记录。填错资料、被他人抢先占用或超期关闭时，通过原淘宝订单人工核实处理，不能绕过核单或盲目重建。Session Key 和淘宝订单号加密存储，查询凭证仅存摘要；公共结果只显示尾号。待核单超过 7 天关闭并删除完整 Session Key，出结果 7 天后删除完整值，受管备份同步清除。淘宝订单号保留用于售后核对及重复受理防护。

支持时段由用户确认：9:00–23:00，时区尚未补充。客服渠道后续填写，目前引导从淘宝原订单联系商家。具体协助动作、交付承诺必须在原淘宝商品与订单约定中真实说明，本站结果不代表 Claude 官方 KYC 通过。

首次部署若尚无后台密码，安装器会生成随机初始密码，写入服务器 `/etc/gettoken/verify-admin.initial-password`（root 所有、0600），数据库仅存哈希，日志不输出密码。已有密码和登录会话不会被替换。管理员通过服务器私密取用，或运行 `sudo gettoken-verify passwd` 设置自己的密码；改密后可删除初始密码文件。显式暂停标志仍保留，不会因初始化而解除。
