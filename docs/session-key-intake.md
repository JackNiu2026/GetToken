# Session Key 提交与查询

按用户最新要求，取消淘宝订单入口。新提交只填写本人 Session Key，确认账户归属与授权后直接进入人工处理，不需要订单号、截图或付款。预计 12 小时的计时从提交开始，仅供参考，不会自动决定结果。

原浏览器用受理编号或最近提交记录查询；跨设备保存完整私密查询链接。查询框不接受 Session Key，不能把完整会话凭据当作口令或放到 URL。提交后的查询凭证仍随机生成、服务器只存摘要，完整 Key 加密保存且不写入浏览器持久存储；出结果 7 天后从数据库与受管备份清除完整值。

同一 Key 已有待处理记录时返回 409，不泄露现有编号或查询凭证。使用原查询链接查看状态，失败请求保留草稿；处理结束后可重新提交。后台默认显示处理中记录，管理员填写交付说明或失败原因后录入结果。新记录没有交易金额、收付款或退款状态。

现有后台账号与访问凭证不变。没有后台账号时仍由安装器仅首次生成随机初始密码，保存在服务器 `/etc/gettoken/verify-admin.initial-password`（root:root、0600），不会输出到日志。管理员可用 `sudo gettoken-verify passwd` 自行设定密码。暂停资料提交继续使用 `VERIFY_ACCEPT_EXTERNAL_ORDERS=false`，不会恢复站内付款。

已有淘宝与财务记录保留，旧查询链接仍然有效，不把历史付款改成免费记录。新 API 配置明确返回 `submissionMode: session-key`，旧淘宝提交字段会拒绝。所有 CSS 文件保持不变；页面只移除订单号步骤、更新文案与必要交互。

本轮本地验收：100 项 Node 22 自动测试、5 项 Python 检查、桌面/手机 Chromium 27 项、打包 API 与真实 Nginx/TLS 23 项通过。全部使用虚构资料，未产生支付与退款记录。上线后继续只读核验新提交模式、开放状态和部署版本。

界面更新：提交结果中的主按钮复制受理编号，适用于原浏览器查询；同一信息框保留跨设备私密查询链接。侧栏“结果查询”和加长的通过信息流保持固定尺寸，电脑端在主操作区滚动吸附，手机端顺序排列。信息流仅展示已同意公开的打码记录，记录超出窗口时自动纵向滚动，可暂停；减少动态效果设置会关闭动画。统计卡片展示今日通过与累计通过（包含未公开通过记录的汇总，不公开其明细），今日沿用站点北京时间口径。
